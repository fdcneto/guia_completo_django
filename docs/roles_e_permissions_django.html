Controle de Acesso Profissional no Django

Roles, Permissions e Autorização Real com Django REST Framework

Conceito Arquitetura Roles (Groups) Permissions Permissão Customizada Aplicação nas Views

1. Conceito Fundamental

Em sistemas profissionais, login não é segurança. Login apenas identifica o usuário. Controle de acesso define o que ele pode fazer.

  • ✅ Autenticação → Quem é você?
  • ✅ Autorização → O que você pode fazer?
O frontend nunca decide permissões. A API é soberana.

2. Arquitetura Profissional de Acesso

Essa separação garante:

  • Segurança
  • Testabilidade
  • Escalabilidade

3. Roles usando Groups

No Django, Group representa um papel (role). Exemplos comuns:

  • admin → controle completo
  • user → acesso limitado

Os grupos podem ser cadastrados via Django Admin ou programaticamente. 


from django.contrib.auth.models import Group

admin = Group.objects.create(name="admin")
user = Group.objects.create(name="user")

4. Permissions (O que cada role pode fazer)

O Django cria permissões automaticamente para cada model:

  • add_model
  • change_model
  • delete_model
  • view_model

Exemplo: permitir delete apenas para admins. 


from django.contrib.auth.models import Permission

perm = Permission.objects.get(codename="delete_task")
admin.permissions.add(perm)

5. Permissão Customizada (Padrão Profissional)

A forma mais comum no mercado é usar classes de permissão próprias. 


from rest_framework.permissions import BasePermission

class IsAdmin(BasePermission):
    def has_permission(self, request, view):
        return (
            request.user.is_authenticated and
            request.user.groups.filter(name="admin").exists()
        )

✅ Reutilizável
✅ Independe do frontend

6. Aplicando Permissões nas Views

Podemos aplicar permissões por ação, aumentando o controle sem duplicar código. 


from rest_framework.permissions import IsAuthenticated

class TaskViewSet(ModelViewSet):

    def get_permissions(self):
        if self.action == "destroy":
            return [IsAuthenticated(), IsAdmin()]
        return [IsAuthenticated()]

Resultado:

  • Usuário comum → listar e criar tarefas
  • Admin → pode deletar
  • API bloqueia acessos indevidos
