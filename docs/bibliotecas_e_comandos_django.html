1. Django Core (Fundamentos Conceituais)

O Django é estruturado em torno do padrão MTV (Model-Template-View), uma variação do MVC. Os módulos core implementam essa arquitetura e definem o fluxo de processamento de uma requisição web — desde a URL até a resposta renderizada.

Fluxo Django: URL → View (lógica) → Model (dados) → Template (apresentação) → Resposta HTTP

django.db.models

Este é o coração da camada de persistência do Django. O ORM (Object-Relational Mapper) não é apenas um "tradutor" SQL, mas uma camada de abstração completa que:

  • Mapeia classes Python para tabelas SQL automaticamente
  • Fornece uma API de consulta intuitiva (QuerySet API)
  • Gerencia relacionamentos (ForeignKey, ManyToMany, OneToOne)
  • Oferece validação de dados no nível do modelo
  • Suporta transações e operações atômicas
from django.db import models

class Task(models.Model):
    # CharField se torna VARCHAR no SQL
    title = models.CharField(
        max_length=100,
        verbose_name="Título da Tarefa",
        help_text="Digite um título descritivo"
    )
    
    # BooleanField com valor padrão
    completed = models.BooleanField(
        default=False,
        verbose_name="Concluída"
    )
    
    # Auto-criação de timestamp
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)
    
    # Relacionamento ForeignKey (muitas tarefas para um usuário)
    user = models.ForeignKey(
        'auth.User',
        on_delete=models.CASCADE,
        related_name='tasks'
    )
    
    def __str__(self):
        return f"{self.title} - {'Concluída' if self.completed else 'Pendente'}"
    
    class Meta:
        ordering = ['-created_at']
        verbose_name = "Tarefa"
        verbose_name_plural = "Tarefas"

django.urls

O sistema de roteamento do Django é declarativo e hierárquico. Cada projeto possui um arquivo urls.py raiz que pode incluir outros arquivos de URLs de apps específicos, criando uma árvore de roteamento.

  • path(): para rotas simples
  • re_path(): para rotas com regex
  • include(): para modularização
  • Namespace: para evitar conflitos entre apps
from django.urls import path, include
from django.contrib import admin
from . import views

# URL patterns principais do projeto
urlpatterns = [
    # Rota para admin Django
    path('admin/', admin.site.urls),
    
    # Rota simples direta para view
    path('', views.home, name='home'),
    
    # Rota com parâmetro dinâmico (captura um inteiro)
    path('tasks/<int:task_id>/', views.task_detail, name='task-detail'),
    
    # Inclusão modular: delega rotas começando com 'api/' para outro arquivo
    path('api/', include('api.urls', namespace='api')),
    
    # Rota com prefixo e namespace para app de usuários
    path('accounts/', include('users.urls', namespace='users')),
]

django.http

Este módulo define os objetos fundamentais do protocolo HTTP no Django:

  • HttpRequest: Contém todos os dados da requisição (GET, POST, headers, sessão, usuário autenticado)
  • HttpResponse: Resposta HTTP básica (status code, headers, conteúdo)
  • JsonResponse: Resposta com conteúdo JSON automaticamente serializado
  • FileResponse: Para servir arquivos
  • StreamingHttpResponse: Para respostas em fluxo contínuo
from django.http import HttpResponse, JsonResponse, Http404
from django.core.serializers import serialize

def api_task_detail(request, task_id):
    """
    Exemplo de view que retorna diferentes tipos de resposta
    baseado no parâmetro 'format' da query string
    """
    try:
        task = Task.objects.get(id=task_id)
    except Task.DoesNotExist:
        raise Http404("Tarefa não encontrada")
    
    format_type = request.GET.get('format', 'html')
    
    if format_type == 'json':
        # Retorna JSON serializado
        return JsonResponse({
            'id': task.id,
            'title': task.title,
            'completed': task.completed,
            'created_at': task.created_at.isoformat()
        })
    elif format_type == 'xml':
        # Retorna XML (usando serializador Django)
        xml_data = serialize('xml', [task])
        return HttpResponse(xml_data, content_type='application/xml')
    else:
        # Retorna HTML simples
        return HttpResponse(f"<h1>{task.title}</h1><p>Status: {task.completed}</p>")

django.shortcuts

São funções utilitárias que encapsulam padrões comuns, reduzindo código boilerplate e melhorando a legibilidade:

  • render(): Combina template + contexto + request → HttpResponse
  • redirect(): Redirecionamento HTTP (302/301)
  • get_object_or_404(): Busca ou retorna 404 automaticamente
  • get_list_or_404(): Busca lista ou retorna 404
  • resolve_url(): Resolve qualquer tipo de URL (path name, URL absoluta, objeto com get_absolute_url)
from django.shortcuts import render, redirect, get_object_or_404
from django.contrib.auth.decorators import login_required
from .forms import TaskForm

@login_required
def create_task(request):
    """
    View que demonstra múltiplos shortcuts em ação
    """
    if request.method == 'POST':
        form = TaskForm(request.POST)
        if form.is_valid():
            task = form.save(commit=False)
            task.user = request.user  # Associa ao usuário logado
            task.save()
            # Redireciona para a página de detalhe da tarefa criada
            return redirect('task-detail', task_id=task.id)
    else:
        form = TaskForm()
    
    # Renderiza template com formulário
    return render(request, 'tasks/create.html', {
        'form': form,
        'title': 'Nova Tarefa'
    })

def task_detail(request, task_id):
    """
    View que usa get_object_or_404 para tratamento elegante de erros
    """
    task = get_object_or_404(Task, id=task_id, user=request.user)
    return render(request, 'tasks/detail.html', {'task': task})

2. Comandos Essenciais do Django (CLI)

O manage.py é o ponto de entrada para todas as operações administrativas do Django. Ele encapsula o Django-admin com as configurações do seu projeto.

Dica de Estrutura: Um projeto Django bem organizado geralmente contém múltiplos apps, cada um com responsabilidade específica (ex: `users`, `products`, `orders`, `blog`).

Criar projeto (startproject)

Cria a estrutura básica do projeto com configurações globais:

  • settings.py: Configurações do projeto (BD, apps instalados, middlewares)
  • urls.py: Roteamento principal
  • wsgi.py: Ponto de entrada para servidores WSGI (ex: Gunicorn)
  • asgi.py: Ponto de entrada para ASGI (ex: Daphne, para WebSockets)
# Cria projeto chamado 'config' (boas práticas modernas)
django-admin startproject config .

# Estrutura criada:
# ├── config/
# │   ├── __init__.py
# │   ├── settings.py
# │   ├── urls.py
# │   ├── wsgi.py
# │   └── asgi.py
# ├── manage.py
# └── requirements.txt

Criar app (startapp)

Cria um módulo funcional dentro do projeto. Cada app deve ter uma responsabilidade única:

  • models.py: Definição dos modelos de dados
  • views.py: Lógica de apresentação
  • urls.py: Roteamento específico do app
  • admin.py: Configuração do painel admin
  • tests.py: Testes unitários
# Cria app para gerenciamento de tarefas
python manage.py startapp tasks

# App criado dentro do projeto:
# tasks/
# ├── migrations/
# │   └── __init__.py
# ├── __init__.py
# ├── admin.py
# ├── apps.py
# ├── models.py
# ├── tests.py
# ├── views.py
# └── urls.py (criado manualmente depois)

Rodar servidor de desenvolvimento (runserver)

Inicia um servidor web leve para desenvolvimento com recursos avançados:

  • Hot Reload: Reinicia automaticamente ao detectar mudanças no código
  • Debug Mode: Página de erros detalhada quando DEBUG = True
  • Static Files: Serve arquivos estáticos automaticamente em desenvolvimento
  • Console SQL: Mostra todas as queries executadas no terminal
# Servidor padrão (localhost:8000)
python manage.py runserver

# Em IP e porta específicos
python manage.py runserver 0.0.0.0:8080

# Com recarga automática desativada (para debug específico)
python manage.py runserver --noreload

Criar migrações (makemigrations)

Gera instruções de migração baseadas nas mudanças nos modelos:

  • Cria arquivos Python em migrations/ com operações de schema
  • Pode ser específico para um app: makemigrations tasks
  • Suporta migrações de dados (RunPython) além de schema
  • Permite nomear migrações: makemigrations --name alter_title_field
# Cria migrações para todos os apps com mudanças
python manage.py makemigrations

# Migração específica para app 'tasks'
python manage.py makemigrations tasks

# Ver SQL que será executado (sem aplicar)
python manage.py sqlmigrate tasks 0001_initial

Aplicar migrações (migrate)

Executa as migrações pendentes no banco de dados:

  • Aplica migrações em ordem de dependência
  • Mantém histórico no Django (django_migrations)
  • Pode reverter migrações (migrate app_name migration_name)
  • Suporta migrações falsas (--fake) para sincronização manual
# Aplica todas as migrações pendentes
python manage.py migrate

# Aplica migrações apenas do app 'tasks'
python manage.py migrate tasks

# Reverte a última migração do app 'tasks'
python manage.py migrate tasks 0001_initial

# Mostra status das migrações
python manage.py showmigrations

Criar superusuário (createsuperuser)

Cria um usuário administrativo para acessar o painel Django Admin:

  • Interativo (pede username, email, password)
  • Pode ser não-interativo via opções de linha de comando
  • Integra-se com sistema de permissões do Django
# Modo interativo (padrão)
python manage.py createsuperuser

# Modo não-interativo (para scripts/containers)
python manage.py createsuperuser \
  --username admin \
  --email admin@example.com \
  --noinput

Comandos Avançados Úteis

# Shell interativo com Django pré-carregado (muito útil!)
python manage.py shell

# Criar arquivos de tradução (i18n)
python manage.py makemessages -l pt_BR

# Compilar traduções
python manage.py compilemessages

# Coletar arquivos estáticos para produção
python manage.py collectstatic

# Verificar problemas no projeto
python manage.py check --deploy

Workflow Profissional:
  1. Alterar models.py
  2. python manage.py makemigrations
  3. python manage.py migrate
  4. python manage.py runserver (testar)
  5. Escrever testes em tests.py
  6. python manage.py test
Este ciclo garante evolução segura do schema do banco de dados.

3. Django REST Framework (DRF)

Extensão poderosa que transforma projetos Django em APIs RESTful profissionais. Adiciona serialização, autenticação, permissões, throttling, versionamento e documentação automática.

Princípio DRF: Separação clara entre serialização (dados), views (lógica) e renderização (formato de saída: JSON, XML, etc).

Serializers

Os serializers fazem a ponte entre objetos Python complexos e formatos de dados serializáveis (JSON, XML, YAML). Eles são responsáveis por:

  • Serialização: Converte objetos QuerySet/Model → JSON
  • Desserialização: Valida JSON recebido → Objetos Python
  • Validação: Regras de validação em campo e objeto
  • Transformação: Computa campos derivados, formata datas, etc
from rest_framework import serializers
from django.contrib.auth.models import User
from .models import Task

class UserSerializer(serializers.ModelSerializer):
    """Serializer para modelo User padrão do Django"""
    class Meta:
        model = User
        fields = ['id', 'username', 'email', 'date_joined']
        read_only_fields = ['date_joined']

class TaskSerializer(serializers.ModelSerializer):
    """
    Serializer avançado com campos personalizados,
    validações e relacionamentos aninhados
    """
    
    # Campo somente leitura computado
    status = serializers.SerializerMethodField()
    
    # Campo relacionado aninhado (nested relationship)
    user = UserSerializer(read_only=True)
    
    # Campo write-only para criação (não aparece na leitura)
    user_id = serializers.PrimaryKeyRelatedField(
        queryset=User.objects.all(),
        source='user',
        write_only=True
    )
    
    class Meta:
        model = Task
        fields = [
            'id', 'title', 'completed', 'created_at', 
            'updated_at', 'status', 'user', 'user_id'
        ]
        read_only_fields = ['id', 'created_at', 'updated_at']
        
        # Validações extras no nível do objeto
        validators = [
            serializers.UniqueTogetherValidator(
                queryset=Task.objects.all(),
                fields=['title', 'user'],
                message="Você já tem uma tarefa com este título"
            )
        ]
    
    def get_status(self, obj):
        """Método para campo computado"""
        return "completed" if obj.completed else "pending"
    
    def validate_title(self, value):
        """Validação em nível de campo"""
        if len(value.strip()) < 3:
            raise serializers.ValidationError(
                "O título deve ter pelo menos 3 caracteres"
            )
        return value.strip()
    
    def validate(self, data):
        """Validação em nível de objeto"""
        if data.get('completed') and not data.get('title'):
            raise serializers.ValidationError({
                'title': "Tarefas concluídas devem ter título"
            })
        return data

Views e ViewSets

O DRF oferece múltiplas abstrações para criar views de API:

  • APIView: Similar às views do Django, mas com métodos HTTP específicos
  • GenericAPIView + Mixins: Combina funcionalidades comuns (CRUD)
  • ViewSets: Agrupa operações relacionadas em um único conjunto
  • ModelViewSet: Fornece todas as operações CRUD para um modelo
from rest_framework import viewsets, permissions, filters
from rest_framework.decorators import action
from rest_framework.response import Response
from django_filters.rest_framework import DjangoFilterBackend
from .models import Task
from .serializers import TaskSerializer

class TaskViewSet(viewsets.ModelViewSet):
    """
    ViewSet que fornece todas as operações CRUD para Task
    Inclui endpoints personalizados e filtragem avançada
    """
    queryset = Task.objects.all()
    serializer_class = TaskSerializer
    
    # Configurações de permissão
    permission_classes = [permissions.IsAuthenticated]
    
    # Filtros e ordenação
    filter_backends = [
        DjangoFilterBackend,
        filters.SearchFilter,
        filters.OrderingFilter
    ]
    filterset_fields = ['completed', 'created_at']
    search_fields = ['title', 'user__username']
    ordering_fields = ['created_at', 'updated_at', 'title']
    ordering = ['-created_at']  # Ordenação padrão
    
    def get_queryset(self):
        """
        Restringe o queryset às tarefas do usuário atual
        (security by default)
        """
        user = self.request.user
        return Task.objects.filter(user=user)
    
    def perform_create(self, serializer):
        """
        Hook para personalizar a criação
        Atribui automaticamente o usuário logado
        """
        serializer.save(user=self.request.user)
    
    @action(detail=True, methods=['post'])
    def mark_completed(self, request, pk=None):
        """
        Endpoint personalizado: marca tarefa como concluída
        Acessível em POST /api/tasks/{id}/mark_completed/
        """
        task = self.get_object()
        task.completed = True
        task.save()
        serializer = self.get_serializer(task)
        return Response(serializer.data)
    
    @action(detail=False)
    def completed_tasks(self, request):
        """
        Endpoint personalizado: lista apenas tarefas concluídas
        Acessível em GET /api/tasks/completed_tasks/
        """
        completed_tasks = self.get_queryset().filter(completed=True)
        page = self.paginate_queryset(completed_tasks)
        if page is not None:
            serializer = self.get_serializer(page, many=True)
            return self.get_paginated_response(serializer.data)
        
        serializer = self.get_serializer(completed_tasks, many=True)
        return Response(serializer.data)

Autenticação e Permissões

Sistema flexível de segurança:

  • Autenticação: Token, Session, Basic, JWT (via djangorestframework-simplejwt)
  • Permissões: IsAuthenticated, IsAdminUser, IsAuthenticatedOrReadOnly, DjangoModelPermissions
  • Throttling: Limitação de requisições (AnonRateThrottle, UserRateThrottle)
# Configuração típica no settings.py
REST_FRAMEWORK = {
    'DEFAULT_AUTHENTICATION_CLASSES': [
        'rest_framework.authentication.SessionAuthentication',
        'rest_framework.authentication.TokenAuthentication',
        'rest_framework_simplejwt.authentication.JWTAuthentication',
    ],
    'DEFAULT_PERMISSION_CLASSES': [
        'rest_framework.permissions.IsAuthenticated',
    ],
    'DEFAULT_THROTTLE_CLASSES': [
        'rest_framework.throttling.AnonRateThrottle',
        'rest_framework.throttling.UserRateThrottle',
    ],
    'DEFAULT_THROTTLE_RATES': {
        'anon': '100/day',
        'user': '1000/hour'
    },
    'DEFAULT_RENDERER_CLASSES': [
        'rest_framework.renderers.JSONRenderer',
        'rest_framework.renderers.BrowsableAPIRenderer',  # Interface web
    ],
    'DEFAULT_PAGINATION_CLASS': 'rest_framework.pagination.PageNumberPagination',
    'PAGE_SIZE': 20
}

Roteamento Automático

# api/urls.py
from rest_framework.routers import DefaultRouter
from .views import TaskViewSet

router = DefaultRouter()
router.register(r'tasks', TaskViewSet, basename='task')

# URLs geradas automaticamente:
# /api/tasks/ - GET (list), POST (create)
# /api/tasks/{id}/ - GET (retrieve), PUT (update), PATCH (partial), DELETE
# /api/tasks/{id}/mark_completed/ - POST (custom action)
# /api/tasks/completed_tasks/ - GET (custom action)

urlpatterns = router.urls

4. Bibliotecas Extras Recomendadas

O ecossistema Django é ampliado por bibliotecas de terceiros que resolvem problemas comuns:

django-debug-toolbar

Painel de debug que mostra queries SQL, tempo de execução, templates renderizados, cache, signals e muito mais. Essencial para otimização.

# settings.py
INSTALLED_APPS += ['debug_toolbar']
MIDDLEWARE += ['debug_toolbar.middleware.DebugToolbarMiddleware']

# Apenas em desenvolvimento
INTERNAL_IPS = ['127.0.0.1']

django-crispy-forms

Renderiza formulários Django com templates HTML modernos (Bootstrap, Tailwind, etc).

# forms.py
from django import forms
from crispy_forms.helper import FormHelper
from crispy_forms.layout import Submit

class TaskForm(forms.ModelForm):
    class Meta:
        model = Task
        fields = ['title', 'completed']
    
    def __init__(self, *args, **kwargs):
        super().__init__(*args, **kwargs)
        self.helper = FormHelper()
        self.helper.add_input(Submit('submit', 'Salvar Tarefa'))

django-filter

Sistema de filtragem avançada para querysets, especialmente útil com DRF.

# filters.py
import django_filters
from .models import Task

class TaskFilter(django_filters.FilterSet):
    created_after = django_filters.DateFilter(
        field_name='created_at', 
        lookup_expr='gte'
    )
    
    class Meta:
        model = Task
        fields = {
            'title': ['icontains'],
            'completed': ['exact'],
            'created_at': ['gte', 'lte', 'exact'],
        }

django-environ

Gerencia configurações sensíveis via variáveis de ambiente.

# config/settings.py
import environ

env = environ.Env()
environ.Env.read_env()

SECRET_KEY = env('SECRET_KEY')

    'default': env.db('DATABASE_URL')
}

django-allauth

Sistema completo de autenticação com redes sociais (Google, Facebook, GitHub), email verification, etc.

Dicas de Produção:

  • celery + redis para tarefas assíncronas
