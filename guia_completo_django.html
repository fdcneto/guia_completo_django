🔧Instalação e Configuração do Ambiente

1Criar Pasta do Projeto

Terminal/CMD 
mkdir meu-projeto-django
cd meu-projeto-django

Este será o diretório raiz do seu projeto.

2Criar e Ativar Ambiente Virtual

Windows (PowerShell) 
python -m venv .venv
.venv\Scripts\Activate.ps1
Linux/macOS 
python3 -m venv .venv
source .venv/bin/activate
💡 Dica: Se encontrar erro de permissão no Windows, execute antes: Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

3Instalar Django e Dependências

pip 
pip install django

Para projetos com API REST e CORS:

pip install django djangorestframework django-cors-headers python-dotenv

📖Entendendo a Sintaxe do Django

Django não é uma linguagem, mas possui algumas "mini-sintaxes" próprias além do Python padrão. Vamos entender cada uma:

1. Python (Base de Tudo)

Toda lógica do Django é feita em Python: models, views, urls, admin, migrations.

class Post(models.Model):
    title = models.CharField(max_length=200)
    created_at = models.DateTimeField(auto_now_add=True)

2. Django Template Language (DTL)

Dentro do HTML, Django usa marcas especiais para lógica simples:

<!-- Exibir variáveis com {{ }} -->
<h1>{{ post.title }}</h1>

<!-- Comandos com {% %} -->
{% for post in posts %}
    <li>{{ post.title }}</li>
{% endfor %}
  • {{ }} - Exibe variáveis e expressões
  • {% %} - Executa comandos (for, if, load, block)

3. Sintaxe das URLs

URLs usam uma sintaxe para capturar variáveis da rota:

path("posts/<int:id>/", views.post_detail)
path("user/<str:username>/", views.user_profile)

4. Django ORM (Consultas ao Banco)

Consultas usando API Python ao invés de SQL direto:

# Buscar todos os posts
Post.objects.all()

# Filtrar posts
Post.objects.filter(title__icontains="django")

# Buscar um único objeto
Post.objects.get(id=1)

🎯Criando seu Primeiro Projeto

4Criar Projeto Django

django-admin 
django-admin startproject meu_site .

O ponto final . significa "criar aqui". Isso gera manage.py e a pasta meu_site com as configurações.

5Estrutura do Projeto

Após criar o projeto, você terá a seguinte estrutura:

meu_site/
    ├── manage.py           # Comandos do Django
    └── meu_site/
        ├── __init__.py
        ├── settings.py     # Configurações
        ├── urls.py         # URLs principais
        ├── asgi.py
        └── wsgi.py

6Executar o Servidor

manage.py 
python manage.py runserver

Acesse no navegador: http://127.0.0.1:8000/

Se ver a página de boas-vindas do Django, está tudo funcionando! 🎉

📦Trabalhando com Apps

Um projeto Django pode ter múltiplos apps. Pense no app como uma caixinha que faz uma coisa específica (ex: blog, loja, autenticação).

7Criar um App

manage.py 
python manage.py startapp blog

Isso cria a pasta blog/ com:

  • models.py - Define a estrutura dos dados
  • views.py - Lógica das páginas
  • admin.py - Configuração do painel admin
  • tests.py - Testes automatizados

8Registrar o App

No arquivo meu_site/settings.py, adicione em INSTALLED_APPS:

INSTALLED_APPS = [

    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',

]

🗄️Models e Banco de Dados

Models são classes Python que definem a estrutura dos dados. Django converte automaticamente em tabelas SQL.

9Definir um Model

No arquivo blog/models.py:

from django.db import models

class Post(models.Model):
    title = models.CharField(max_length=200)
    content = models.TextField()
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)
    
    def __str__(self):
        return self.title
    
    class Meta:
        ordering = ['-created_at']
💡 Tipos de campos comuns:
  • CharField - Texto curto
  • TextField - Texto longo
  • IntegerField - Números inteiros
  • DateTimeField - Data e hora
  • BooleanField - Verdadeiro/Falso
  • ForeignKey - Relacionamento

Gerar migrations

🎨Views e URLs

Views são funções (ou classes) que recebem requisições HTTP e retornam respostas.

13Criar Views

No arquivo blog/views.py:

from django.shortcuts import render, get_object_or_404
from .models import Post

def lista_posts(request):
    posts = Post.objects.all()
    return render(request, 'blog/lista_posts.html', {'posts': posts})

def post_detail(request, pk):
    post = get_object_or_404(Post, pk=pk)
    return render(request, 'blog/post_detail.html', {'post': post})

14Configurar URLs do App

Crie o arquivo blog/urls.py:

from django.urls import path
from . import views

urlpatterns = [
    path('', views.lista_posts, name='lista_posts'),
    path('post/<int:pk>/', views.post_detail, name='post_detail'),
]

15Incluir no Projeto

No arquivo meu_site/urls.py:

from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', include('blog.urls')),
]

📝Formulários

19Criar Formulário

Crie o arquivo blog/forms.py:

from django import forms
from .models import Post

class PostForm(forms.ModelForm):
    class Meta:
        model = Post
        fields = ['title', 'content']
        widgets = {
            'title': forms.TextInput(attrs={'class': 'form-control'}),
            'content': forms.Textarea(attrs={'class': 'form-control', 'rows': 5}),
        }

20View para Criar Post

No arquivo blog/views.py:

from django.shortcuts import render, redirect
from .forms import PostForm

def criar_post(request):
    if request.method == 'POST':
        form = PostForm(request.POST)
        if form.is_valid():
            form.save()
            return redirect('lista_posts')
    else:
        form = PostForm()
    return render(request, 'blog/criar_post.html', {'form': form})

21Template do Formulário

Arquivo templates/blog/criar_post.html:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
    <meta charset="UTF-8">
    <title>Criar Novo Post</title>
</head>
<body>
    <h1>Criar Novo Post</h1>
    <form method="post">
        {% csrf_token %}
        {{ form.as_p }}
        <button type="submit">Salvar</button>
    </form>
    <a href="{% url 'lista_posts' %}">Cancelar</a>
</body>
</html>
⚠️ Importante: O {% csrf_token %} é obrigatório em todos os formulários para proteção contra ataques CSRF.

🔄CRUD Completo

Vamos implementar as operações de Edição e Exclusão para completar o CRUD:

22View de Edição

No arquivo blog/views.py:

def editar_post(request, pk):
    post = get_object_or_404(Post, pk=pk)
    if request.method == 'POST':
        form = PostForm(request.POST, instance=post)
        if form.is_valid():
            form.save()
            return redirect('lista_posts')
    else:
        form = PostForm(instance=post)
    return render(request, 'blog/editar_post.html', {'form': form, 'post': post})

23View de Exclusão

def excluir_post(request, pk):
    post = get_object_or_404(Post, pk=pk)
    if request.method == 'POST':
        post.delete()
        return redirect('lista_posts')
    return render(request, 'blog/confirmar_exclusao.html', {'post': post})

🔐Sistema de Autenticação

Django possui um sistema completo de autenticação já incluído. Vamos implementá-lo:

26Criar App de Autenticação

python manage.py startapp account

Adicione 'account', em INSTALLED_APPS no settings.py.

27View de Registro

No arquivo account/views.py:

from django.contrib.auth.forms import UserCreationForm
from django.urls import reverse_lazy
from django.views import generic

class RegisterView(generic.CreateView):
    form_class = UserCreationForm
    success_url = reverse_lazy('login')
    template_name = 'account/register.html'

28View de Login Customizada (Opcional)

Se preferir uma view customizada:

from django.contrib.auth import authenticate, login
from django.shortcuts import render, redirect
from django.contrib import messages

def custom_login(request):
    if request.method == 'POST':
        username = request.POST.get('username')
        password = request.POST.get('password')
        user = authenticate(request, username=username, password=password)
        if user is not None:
            login(request, user)
            return redirect('lista_posts')
        else:
            messages.error(request, 'Usuário ou senha inválidos.')
    return render(request, 'account/login.html')

29View de Logout

from django.contrib.auth import logout

def custom_logout(request):
    logout(request)
    return redirect('login')

30URLs de Autenticação

Crie account/urls.py:

from django.urls import path
from django.contrib.auth import views as auth_views
from . import views

urlpatterns = [
    path('register/', views.RegisterView.as_view(), name='register'),
    path('login/', auth_views.LoginView.as_view(template_name='account/login.html'), name='login'),
    path('logout/', auth_views.LogoutView.as_view(next_page='login'), name='logout'),
]

Incluir no meu_site/urls.py:

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', include('blog.urls')),
    path('account/', include('account.urls')),
]

    # Código da view
    pass

@login_required

    # Código da view
    pass

35Proteção por Permissões

Para controle mais fino de acesso:

from django.contrib.auth.decorators import permission_required

# Definir permissão no model
class Post(models.Model):
    # campos...
    class Meta:
        permissions = [
            ("can_publish_post", "Pode publicar posts"),
        ]

# Usar na view
@permission_required('blog.can_publish_post', login_url='login')
def publicar_post(request, pk):
    # Código da view
    pass

💪Exercícios Práticos

Exercício 1: DTL - Lista Filtrada

  1. Crie uma view que filtre posts contendo "Django" no título
  2. Use Post.objects.filter(title__icontains='Django')
  3. No template, use {% for p in posts %} para listar
  4. Mostre o título e um trecho do conteúdo com {{ p.content|truncatewords:30 }}
  5. Teste criando posts com e sem "Django" no título

Exercício 2: ORM - Consulta com Relacionamento

  1. Adicione um campo author = models.ForeignKey(User, on_delete=models.CASCADE) ao modelo Post
  2. Faça as migrations: makemigrations e migrate
  3. Use Post.objects.select_related('author').all() para evitar queries N+1
  4. No template, mostre {{ post.author.username }}
  5. Verifique as queries executadas no terminal (DEBUG=True)

Exercício 3: URLs - Capturar Slug

  1. Adicione um campo slug = models.SlugField(unique=True) ao Post
  2. Crie uma URL: path('post/<slug:slug>/', views.post_by_slug)
  3. Na view, use get_object_or_404(Post, slug=slug)
  4. Teste acessando /post/meu-primeiro-post/

Exercício 4: CRUD Completo com Class-Based Views

  1. Converta as views de função para Class-Based Views
  2. Use ListView, DetailView, CreateView, UpdateView, DeleteView
  3. Exemplo: class PostListView(ListView): model = Post
  4. Compare o código antes e depois

🎓Conceitos Importantes

MTV Architecture

  • Model: Estrutura dos dados (ORM)
  • Template: Interface visual (HTML)
  • View: Lógica de negócios

ORM (Object-Relational Mapping)

Sistema que converte classes Python em tabelas SQL automaticamente, permitindo trabalhar com banco de dados usando Python puro.

Migrations

Sistema de controle de versão do banco de dados. Cada mudança nos models gera uma migration que pode ser aplicada ou revertida.

QuerySets

Objetos que representam consultas ao banco. São lazy (só executam quando necessário) e podem ser encadeados.

Middleware

Camada de processamento entre requisição e resposta. Usado para autenticação, CSRF, sessões, etc.

Context Processors

Funções que adicionam variáveis automaticamente a todos os templates.

⚠️Erros Comuns e Soluções

Template não encontrado?

Verifique TEMPLATES[0]['DIRS'] no settings.py e certifique-se que a pasta templates/ existe.

Erro 500 no terminal?

Leia o traceback completo - ele indica exatamente qual arquivo e linha está com problema.

Migrations não aplicam?

Execute python manage.py showmigrations para ver o status. Se houver conflito, use python manage.py migrate --fake com cuidado.

Static files não aparecem?

Em desenvolvimento, verifique se django.contrib.staticfiles está em INSTALLED_APPS e use {% load static %} nos templates.

CSRF verification failed?

Certifique-se de incluir {% csrf_token %} em todos os formulários POST.
